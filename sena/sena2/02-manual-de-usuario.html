1. Presentación del sistema

1.1 Qué hace el sistema

API RiwiMediCare Plus administra el ciclo completo de las solicitudes de abastecimiento de medicamentos e insumos médicos de una empresa distribuidora. Permite:

  • Registrar las clínicas atendidas y a sus responsables.
  • Administrar el catálogo de medicamentos y los almacenes de despacho.
  • Llevar el control de cuántas unidades hay de cada medicamento en cada almacén.
  • Radicar solicitudes de abastecimiento verificando que haya existencias.
  • Aprobar, rechazar, entregar o cancelar cada solicitud, descontando y reintegrando el inventario de forma automática.
  • Consultar el historial completo de solicitudes, general o por clínica.

1.2 A quién está dirigido

Tabla 1. Perfiles de usuario del sistema.
PerfilQué puede hacer
AdministradorTodas las operaciones. Es el único que puede crear, modificar y dar de baja clínicas, almacenes, medicamentos e inventario, y el único que puede corregir o dar de baja solicitudes.
GestorConsultar toda la información, radicar solicitudes y cambiarles el estado. No puede modificar datos maestros ni dar de baja registros.

1.3 Cómo se usa una API

Antes de empezar Este sistema es una API REST: la capa de servidor de la aplicación. No tiene ventanas ni botones propios. Se opera enviando peticiones HTTP, y este manual utiliza Swagger UI, la interfaz web que el propio sistema publica para consultar y ejecutar cada operación directamente desde el navegador, sin instalar nada adicional.

Toda operación del sistema se identifica por la combinación de un verbo y una ruta:

Tabla 2. Verbos HTTP empleados y su significado.
VerboSignificadoEjemplo en el sistema
GETConsultarGET /api/clinicas devuelve las clínicas
POSTCrearPOST /api/solicitudes radica una solicitud
PUTActualizar por completoPUT /api/clinicas/:id actualiza una clínica
PATCHActualizar en partePATCH /api/solicitudes/:id/estado cambia el estado
DELETEDar de bajaDELETE /api/clinicas/:id desactiva una clínica

El sistema responde siempre en formato JSON y acompaña cada respuesta con un código numérico:

Tabla 3. Códigos de respuesta que devuelve el sistema.
CódigoSignificadoCuándo aparece
200CorrectoLa consulta o la actualización se realizó.
201CreadoEl registro se creó correctamente.
400Datos incorrectosFaltan campos, la cantidad es inválida, no hay inventario suficiente o la transición de estado no es válida.
401Sin autenticarNo se envió token, o está vencido o alterado.
403Sin permisosEl usuario está autenticado pero su rol no autoriza esa operación.
404No encontradoEl registro solicitado no existe o fue dado de baja.
409ConflictoYa existe un registro con esos datos, o la operación contradice el estado actual.
500Error del servidorFallo interno no previsto.

Solo requiere Docker Desktop. Levanta la API y la base de datos en contenedores con un único comando.

3.2 Opción B: instalación con Docker

Levanta dos contenedores conectados por una red interna: la API y PostgreSQL. No requiere instalar Node ni PostgreSQL en el equipo.

# 1. Descargar el codigo
git clone https://github.com/DylanSrz/pd_node.git
cd pd_node

# 2. Crear el archivo de variables
cp .env.example .env

# 3. Levantar los dos contenedores
docker compose up -d

# 4. Ver los registros de la API
docker compose logs -f api

# 5. Crear las tablas dentro del contenedor
docker compose exec api npm run migrate

# 6. Cargar los datos de prueba
docker compose exec api npm run seed
FIGURA 8 Salida de docker compose up -d con los dos contenedores iniciados

ComandoQué hace

docker compose down -vElimina también el volumen. Se pierden todos los datos.
docker compose restart apiReinicia solo el contenedor de la API.

3.3 Restaurar desde el respaldo

Como alternativa a ejecutar migraciones y seeders, el repositorio incluye backup.sql, un respaldo completo con estructura y datos ya cargados.

5.4 Autorizar la sesión en Swagger

Los cuatro pasos para autorizar
  1. Copie el valor completo del campo token, sin las comillas.
  2. Pulse el botón Authorize en la parte superior derecha de Swagger.
  3. Pegue el token en el campo. No escriba la palabra Bearer: Swagger la agrega por su cuenta.
  4. Pulse Authorize y después Close. El candado se cierra y ya puede ejecutar el resto de endpoints.
FIGURA 13 Cuadro de diálogo Authorize de Swagger con el token pegado

Figura 13. Autorización de la sesión en Swagger.

Vigencia del token El token expira a las 8 horas, según el valor de JWT_EXPIRES_IN. Al expirar, todas las peticiones responden 401 con el mensaje Token inválido o expirado. La solución es repetir el inicio de sesión y volver a autorizar con el token nuevo.

6.4 Radicar una solicitud de abastecimiento

POST /api/solicitudes — gestor y administrador

{
  "clinica_id": "uuid-de-la-clinica",
  "medicamento_id": "uuid-del-medicamento",
  "almacen_id": "uuid-del-almacen",
  "cantidad_solicitada": 120,
  "observaciones": "Reposicion mensual del servicio de urgencias"
}
Qué comprueba el sistema antes de aceptarla
  1. Que el token sea válido y el rol esté autorizado.
  2. Que los cuatro campos tengan formato correcto y la cantidad sea un entero mayor que cero.
  3. Que la clínica, el medicamento y el almacén existan y estén activos.
  4. Que el almacén maneje ese medicamento y tenga unidades suficientes.

Si todo se cumple, la solicitud se crea en estado pendiente. El inventario aún no se descuenta.

No se envía usuario_id: el sistema lo toma del token, de modo que nadie puede radicar una solicitud a nombre de otra persona. Tampoco se envía estado: toda solicitud nace pendiente.

Error al iniciar la aplicación
ECONNREFUSED		PostgreSQL no está en ejecución, o los datos del .env no son correctos.Verifique que el servicio de PostgreSQL esté iniciado y que el host, el puerto, el usuario y la contraseña del .env coincidan con su instalación.
database "db_nodejs" does not existNo se creó la base de datos antes de ejecutar las migraciones.Ejecute createdb -U admin db_nodejs y repita npm run migrate.
relation "users" does not existNo se ejecutaron las migraciones.Ejecute npm run migrate.
npm run seed no carga nadaLa tabla SequelizeData conserva el registro de seeders ya ejecutados, aunque las tablas se hayan borrado.Ejecute en este orden: seed:reset, migrate:reset, migrate, seed.
401 en todos los endpointsNo se pulsó Authorize, o el token expiró.Repita el inicio de sesión y pegue el token nuevo. Recuerde no escribir la palabra Bearer.
403 en operaciones de creaciónInició sesión con un usuario de rol gestor.Inicie sesión con un usuario administrador.
Falta configurar JWT_SECRETLa variable no está definida en el .env.Agréguela con cualquier texto largo y reinicie el servidor.
El puerto 3000 está ocupadoOtro programa lo está usando.Cambie PORT en el .env a otro valor, por ejemplo 3001.
El contenedor de la API se reiniciaPostgreSQL aún no estaba listo, o el .env falta.Revise docker compose logs api. Confirme que el archivo .env existe en la raíz antes de levantar los contenedores.
Cambios en el código sin efectoEstá ejecutando la versión compilada con npm start.Use npm run dev, que recarga automáticamente, o vuelva a compilar con npm run build.

9.1 Reiniciar todo desde cero

npm run seed:reset      # 1. limpia el registro de los seeders
npm run migrate:reset   # 2. borra las tablas
npm run migrate         # 3. las vuelve a crear
npm run seed            # 4. carga los datos otra vez
