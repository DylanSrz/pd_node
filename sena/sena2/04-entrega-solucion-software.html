4.1 Integración con la base de datos

Tabla 5. Evidencia de la integración con PostgreSQL.
AspectoImplementación verificable
ConexiónInstancia única de Sequelize en config/db.ts, configurada desde variables de entorno.
Esquema versionado6 migraciones numeradas y reversibles, ejecutadas y registradas por Umzug en la tabla migrations.
Integridad referencial6 llaves foráneas declaradas en las migraciones e impuestas por el motor.
Restricciones de unicidad3: correo del usuario, NIT de la clínica y la pareja almacén-medicamento del inventario.
Restricciones de verificación2: cantidad de inventario no negativa y cantidad solicitada mayor que cero.
Tipos enumerados2: roles de usuario y estados de solicitud, definidos en el motor.
TransaccionesEl cambio de estado y la baja de solicitudes se ejecutan dentro de una transacción con rollback ante cualquier fallo.
Control de concurrenciaBloqueo de fila con LOCK.UPDATE sobre el registro de inventario durante la aprobación.
Consultas con relacionesLas consultas de solicitudes e inventario resuelven sus relaciones con include, enumerando explícitamente las columnas devueltas.

5. Guía de verificación para el evaluador

Procedimiento para comprobar el funcionamiento completo del sistema.

5.1 Puesta en marcha

# 1. Obtener el codigo
git clone https://github.com/DylanSrz/pd_node.git
cd pd_node

# 2. Instalar dependencias
npm install

# 3. Configurar el entorno
cp .env.example .env
#    Editar el .env con los datos de PostgreSQL propios

# 4. Crear la base de datos
createdb -U admin db_nodejs

# 5. Crear las tablas y cargar los datos
npm run migrate
npm run seed

# 6. Levantar el servidor
npm run dev

Alternativa con contenedores, sin instalar Node ni PostgreSQL:

docker compose up -d
docker compose exec api npm run migrate
docker compose exec api npm run seed

Los pasos 3, 5, 8 y 10 son el núcleo de la verificación Consultar el inventario cuatro veces a lo largo del recorrido demuestra la regla de negocio central del sistema: crear una solicitud no descuenta inventario, aprobarla sí, y cancelarla lo reintegra. La secuencia de cantidades debe ser, por ejemplo: 500 → 500 → 380 → 500.

5.3 Verificación directa en la base de datos

-- Comprobar que existen las seis tablas del dominio
psql -U admin -d db_nodejs -c "\dt"

-- Comprobar que las restricciones estan declaradas
psql -U admin -d db_nodejs -c "SELECT conname, contype FROM pg_constraint WHERE conrelid = 'solicitudes'::regclass;"

-- Comprobar el tipo enumerado de los estados
psql -U admin -d db_nodejs -c "SELECT enumlabel FROM pg_enum WHERE enumtypid = 'enum_solicitudes_estado'::regtype;"

-- Comprobar que ningun registro se borra fisicamente
psql -U admin -d db_nodejs -c "SELECT estado, is_active, COUNT(*) FROM solicitudes GROUP BY estado, is_active;"

6.1 Antes de radicar la entrega

Comprobaciones finales recomendadas
  1. Confirmar que la rama main del repositorio remoto está actualizada con la versión final.
  2. Verificar que el archivo .env no está versionado y que .env.example sí lo está.
  3. Clonar el repositorio en una carpeta limpia y seguir el numeral 5.1 desde cero, para comprobar que las instrucciones bastan por sí solas.
  4. Confirmar que backup.sql restaura correctamente en una base de datos vacía.
  5. Completar las capturas del manual de usuario siguiendo la guía correspondiente.
  6. Reemplazar los campos marcados en amarillo de las portadas por los datos institucionales reales.
